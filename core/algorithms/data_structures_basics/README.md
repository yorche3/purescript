**ES:** Implementación de `Node`, `LinkedList`, `Stack` y `Queue` sobre el mismo tipo de nodo enlazado, con pruebas unitarias mediante **Test.Unit** (`test-unit`) y **spago** como gestor de paquetes y runner.

**EN:** Implementation of `Node`, `LinkedList`, `Stack` and `Queue` over the same linked node type, with unit tests using **Test.Unit** (`test-unit`) and **spago** as package manager and runner.

## 🧩 Decisiones de diseño / Design decisions

| Decisión / Decision | Alternativa considerada / Alternative | Razón / Reason |
|---|---|---|
| Ausencia como constructor propio: `data Node = Empty \| Node Int Node` | `Maybe (Node ...)` | Esta fase no introduce `Maybe` (el equivalente a `Option`), así que un constructor `Empty` da la ausencia sin tipo opcional y el patrón `Empty`/`Node` cubre los dos casos sin desempaquetar nada |
| Devolver la estructura actualizada en `Tuple` | Devolver solo el valor y exponer el estado por un tipo de estado | Los valores son inmutables: quien llama necesita el término nuevo. La tupla lo entrega junto al resultado (`delete` añade el booleano de éxito) sin introducir un tipo nuevo |
| Un `test` por estructura con los casos dentro | Un `test` por caso de la especificación | La especificación pide pasos sucesivos sobre el mismo estado lógico; con valores inmutables el encadenado solo es posible dentro de un mismo test, y el aislamiento entre tests impide continuar el escenario |
| Reconstruir el camino al añadir por la cola (`appendNode`) | Enlazar la celda de cola en el sitio | La celda de cola está dentro de la cadena que cuelga de la cabeza: enlazarla en el sitio exigiría mutarla. Reconstruir el camino desde la cabeza es la única forma correcta (ver _Limitaciones_) |
| `derive instance Eq Node` | Comparar con patrones `Empty`/`Node` en cada operación | Las operaciones que deciden «¿la cadena cambió?» necesitan comparar nodos; la instancia derivada lo resuelve sin repetir el recorrido en cada sitio |

## 🔀 Adaptaciones idiomáticas / Idiomatic adaptations

| Especificación / Specification | Adaptación / Adaptation | Justificación / Justification |
|---|---|---|
| `init(value)`, `init()` | `initNode`, `initLinkedList`, `initStack`, `initQueue` | PureScript no tiene un `init` por tipo: cada estructura tiene su función, en `camelCase` como exige la convención de nombres del lenguaje |
| `get_value()`, `get_next()`, `set_next(next)` | `getValue`, `getNext`, `setNext` | Misma operación con la capitalización de PureScript; el «objeto» viaja como argumento |
| `delete(value)` con resultado éxito/fallo | `delete :: Int -> LinkedList -> Tuple LinkedList Boolean` | Los valores son inmutables: la lista resultante y el booleano de éxito viajan juntos |
| `pop()`, `dequeue()` devuelven el valor y dejan la estructura extraída | `pop :: Stack -> Tuple Int Stack` y `dequeue :: Queue -> Tuple Int Queue` | No hay estructura «que queda»: la extraída es un valor nuevo y se devuelve en la tupla |
| Insertar al final enlazando la cola | `appendNode` reconstruye la cadena desde la cabeza | Con valores inmutables no se puede modificar la celda de cola, que está dentro de la cadena que cuelga de la cabeza |
| Ausencia de enlace `null`/`nil` | `Empty` | PureScript no tiene `null`: la ausencia es un constructor del tipo `Node`, y es la única que se usa |
| Indicador de fallo `-1` en las lecturas | Se conserva `-1` | El tipo `Int` es total, así que el centinela es representable y no colisiona: los valores de prueba son enteros positivos |
| Ubicación esperada `src/data_structures_basics.ext` y `test/run_tests.ext` | `src/DataStructuresBasics.purs` y `test/Test/DataStructuresBasicsTests.purs` | El layout lo fija spago: el archivo lleva el nombre del módulo en `PascalCase` y el runner es `spago test`, sin script propio |

## 📝 Notas de implementación / Implementation Notes

**ES:** Las cadenas se recorren por recursión sobre el constructor `Node`; no hay bucles ni mutación, así que cada operación devuelve un valor nuevo y comparte los tramos que no cambia. `appendNode` y `findTail` son auxiliares internos: el primero copia la cadena enlazando el nodo nuevo al final y el segundo obtiene la última celda, que es lo que `delete` necesita para dejar la cola apuntando a la celda correcta. `derive instance Eq Node` es lo que permite decidir si una cadena cambió comparando cabezas, y `Test.Unit` (`test-unit`) es el framework de pruebas, con `Assert.assert` para que el fallo lleve el mensaje del contrato: `assert` recibe el mensaje primero y la condición después.

**EN:** Chains are walked by recursion over the `Node` constructor; there are no loops or mutation, so every operation returns a new value and shares the untouched stretches. `appendNode` and `findTail` are internal helpers: the first copies the chain linking the new node at the end and the second gets the last cell, which is what `delete` needs so the tail points at the right cell. `derive instance Eq Node` is what allows deciding whether a chain changed by comparing heads, and `Test.Unit` (`test-unit`) is the test framework, with `Assert.assert` so a failure carries the contract message: `assert` takes the message first and the condition second.
