# Data Structures Advanced — PureScript

Implementación de la especificación [07_Data_Structures_Advanced](../../../../docs/core/algorithms/07_Data_Structures_Advanced.md) en **PureScript**, con un enfoque manual y minimalista.

**ES:** Implementación de `TreeNode`, `BinaryTree` (árbol binario de búsqueda sin capacidad fija) y `Graph` (grafo dirigido con registro enlazado canónico de vértices y adyacencia ordenada) sobre tipos de datos algebraicos inmutables, con pruebas unitarias mediante **Test.Unit** (`test-unit`) y **spago** como gestor de paquetes y runner.

**EN:** Implementation of `TreeNode`, `BinaryTree` (unbounded binary search tree) and `Graph` (directed graph with canonical linked vertex registry and sorted adjacency) over immutable algebraic data types, with unit tests using **Test.Unit** (`test-unit`) and **spago** as package manager and runner.

## 🛠️ Enfoque y construcción / Approach & Build

**ES:** El proyecto se inicializó con la herramienta oficial `spago init`. Las estructuras se implementan manualmente como tipos algebraicos (`data TreeNode`, `newtype BinaryTree`, `newtype GraphNode`, `newtype Graph`) con valores estrictamente inmutables. PureScript no utiliza clases con herencia orientada a objetos: el valor base de `Node` vive embebido como campo de registro (`value :: Int` en `TreeNode` y `label :: Int` en `GraphNode`). El registro de vértices de `Graph` es una lista enlazada propia recorrida recursivamente (`findVertex`), cumpliendo la cota `O(V)` sin delegar en `Map` ni tablas hash. Las adyacencias se insertan ordenadas en un `Array Int` (`positionFor` / `insertNeighbor`), garantizando `O(d(u))` sin ordenar al consultar.

**EN:** The project was initialized using the official `spago init` tool. Structures are manually implemented as algebraic data types (`data TreeNode`, `newtype BinaryTree`, `newtype GraphNode`, `newtype Graph`) with strictly immutable values. PureScript does not feature object-oriented class inheritance: the `Node` base value lives embedded as a record field (`value :: Int` in `TreeNode` and `label :: Int` in `GraphNode`). The vertex registry of `Graph` is a custom linked list traversed recursively (`findVertex`), meeting the `O(V)` bound without delegating to `Map` or hash tables. Adjacencies are inserted in sorted order into an `Array Int` (`positionFor` / `insertNeighbor`), guaranteeing `O(d(u))` without sorting during queries.

## 🧠 Algoritmos y operaciones / Algorithms & Operations

| Operación / Operation | Entrada → salida / Input → output | Complejidad / Complexity | Notas / Notes |

| `newTreeNode` | `Int → TreeNode` | `O(1)` | `init` de TreeNode; ambos enlaces inicializados a `Nothing` |
| `getValue` | `TreeNode → Int` | `O(1)` | Observa el valor embebido del nodo |
| `getLeft` | `TreeNode → Maybe TreeNode` | `O(1)` | Enlace izquierdo, o `Nothing` si es ausente |
| `getRight` | `TreeNode → Maybe TreeNode` | `O(1)` | Enlace derecho, o `Nothing` si es ausente |

| `newBinaryTree` | `→ BinaryTree` | `O(1)` | `init` de BinaryTree; raíz `Nothing` y contador a `0` |
| `insert` | `Int → BinaryTree → BinaryTree` | `O(h)` | Inserta preservando la invariante del ABB; duplicados no incrementan el tamaño |
| `contains` | `Int → BinaryTree → Boolean` | `O(h)` | Búsqueda por ramas según orden del ABB; `false` si no está |
| `isTreeEmpty` | `BinaryTree → Boolean` | `O(1)` | `true` exactamente cuando el contador es cero |

## 🧩 Decisiones de diseño / Design decisions

| Decisión / Decision | Alternativa considerada / Alternative | Razón / Reason |
|---|---|---|
| Reutilización de `Node` por valor embebido | Tipo base común con clases de tipos | PureScript no tiene herencia orientada a objetos de clases; el valor embebido en el registro interno (`value :: Int` y `label :: Int`) satisface la especificación con coste cero y sin abstracciones innecesarias |
| Representación de ausencia con `Maybe` (`Data.Maybe`) | Centinelas numéricos (`-1`) o constructores auxiliares ad-hoc | PureScript pertenece a la familia funcional `func-option` donde la ausencia canónica es `Nothing`. Permite diferenciar limpiamente un vértice aislado (`Just []`) de uno inexistente (`Nothing`) |
| Inmutabilidad estricta y funciones `withLeft` / `withRight` | Mutación mediante `Effect.Ref` o referencias de estado | PureScript favorece la pureza referencial; devolver un nuevo valor inmutable preserva el aislamiento, facilita el razonamiento ecuacional y cumple la adaptación inmutable de la especificación |
| Registro canónico de vértices propio enlazado (`nextVertex`) | `Data.Map` o `Data.HashMap` de biblioteca | La especificación exige explícitamente una implementación manual con búsqueda recursiva/iterativa `O(V)` para comprobar la comprensión del algoritmo sin delegar en colecciones indexadas |
| Adyacencia ordenada construida en la inserción (`positionFor`) | Ordenar el array de vecinos con `sort` en cada llamada a `getNeighbors` | Mantener la secuencia de vecinos siempre ordenada durante la inserción garantiza que `getNeighbors` sea una simple consulta `O(1)` sobre la lista del nodo sin sobrecoste `O(d \log d)` |
| `addEdge` devuelve `Maybe Graph` | Devolver el grafo inalterado o lanzar una excepción | Devolver `Nothing` cuando falta un extremo hace que el fallo sea explícito y total en el sistema de tipos, asegurando que un fallo nunca cree vértices ni mute el grafo |

## 🔀 Adaptaciones idiomáticas / Idiomatic adaptations

| Especificación / Specification | Adaptación / Adaptation | Justificación / Justification |
|---|---|---|
| `type TreeNode extends Node` | `data TreeNode = TreeNode { value :: Int, left :: Maybe TreeNode, right :: Maybe TreeNode }` | PureScript carece de herencia clásica de tipos; el valor se embebe en el constructor |
| `init()`, `init(value)` | `newTreeNode`, `newBinaryTree`, `newGraph` | En PureScript las funciones constructores usan nombres descriptivos en `camelCase` para evitar colisiones |
| `set_left(node)`, `set_right(node)` | `withLeft`, `withRight` | Por inmutabilidad, las operaciones devuelven un nuevo `TreeNode` con el enlace actualizado |
| `add_edge(u, v)` con fallo si falta extremo | `addEdge :: Int -> Int -> Graph -> Maybe Graph` | Los valores son inmutables; el fallo al no existir un extremo devuelve `Nothing` sin mutación colateral |
| Ausencia de enlace `absent` | `Nothing` de `Data.Maybe` | En PureScript no existe `null`; la ausencia se representa con el tipo opcional nativo `Maybe` |
| `get_neighbors(u)` con fallo si `u` no existe | `getNeighbors :: Int -> Graph -> Maybe (Array Int)` | Permite distinguir de forma no ambigua entre vértice inexistente (`Nothing`) y vértice aislado sin aristas salientes (`Just []`) |
| Ubicación esperada `src/data_structures_advanced.ext` y `test/run_tests.ext` | `src/DataStructuresAdvanced.purs` y `test/Test/DataStructuresAdvancedTests.purs` | Layout requerido por el gestor de paquetes del lenguaje (**spago**), que ejecuta las pruebas con `spago test` |

## 📝 Notas de implementación / Implementation Notes

**ES:** PureScript es un lenguaje puramente funcional con evaluación estricta que compila a JavaScript. Todas las estructuras (`TreeNode`, `BinaryTree`, `GraphNode`, `Graph`) son inmutables.
- En `TreeNode`, las operaciones de actualización de enlaces `withLeft` y `withRight` devuelven una nueva instancia del nodo reutilizando los enlaces no modificados.
- En `BinaryTree`, la inserción (`insertNode`) reconstruye únicamente la rama afectada del camino desde la raíz, logrando tiempo `O(h)` y persistencia estructural. La pertenencia (`contains`) se resuelve mediante la función auxiliar `go` que navega el árbol siguiendo la invariante del ABB en `O(h)` sin recorrer secuencias lineales.
- En `Graph`, el registro canónico de vértices se mantiene como una lista enlazada propia a través del campo `nextVertex` de `GraphNode`. La función `findVertex` recorre esta lista de forma recursiva en `O(V)` sin emplear mapas de biblioteca.
- La secuencia de adyacencia de cada vértice se gestiona en un `Array Int`. Para garantizar vecinos ordenados en `O(d(u))` sin ordenar posteriormente durante las consultas, `insertNeighbor` calcula la posición de inserción adecuada con `positionFor` e inserta el valor mediante `insertAt`.
- La ausencia y los fallos de existencia se modelan con `Maybe`: `Nothing` representa la ausencia de nodo o la inexistencia de un vértice en el grafo, mientras que un vértice aislado sin aristas salientes devuelve `Just []`, cumpliendo la distinción estricta exigida por la especificación.
- Las pruebas se estructuran con **Test.Unit** (`test-unit`), empleando `Assert.assert` con mensajes descriptivos para cada verificación.

**EN:** PureScript is a purely functional, strict language targeting JavaScript. All data structures (`TreeNode`, `BinaryTree`, `GraphNode`, `Graph`) are immutable.
- In `TreeNode`, the link update operations `withLeft` and `withRight` return a new node instance while sharing unaffected links.
- In `BinaryTree`, insertion (`insertNode`) reconstructs only the affected path branch from the root, achieving `O(h)` time and structural sharing. Membership (`contains`) uses a helper function `go` navigating the BST invariant in `O(h)` without linear traversals.
- In `Graph`, the canonical vertex registry is maintained as a custom linked list using the `nextVertex` field of `GraphNode`. The `findVertex` function traverses this list recursively in `O(V)` without library map lookups.
- The adjacency sequence of each vertex is kept in an `Array Int`. To guarantee sorted neighbours in `O(d(u))` without sorting during queries, `insertNeighbor` finds the insertion index using `positionFor` and inserts the element via `insertAt`.
- Absence and lookup failures are represented using `Maybe`: `Nothing` indicates an absent link or nonexistent vertex, whereas an isolated vertex with no outgoing edges returns `Just []`, fulfilling the contract's required distinction.
- Tests are organized using **Test.Unit** (`test-unit`), utilizing `Assert.assert` with descriptive messages for each assertion.
